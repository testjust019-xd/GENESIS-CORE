# Learning & Evaluation (initial)

GENESIS can create a user-directed curriculum with its configured primary model, persist the lessons, and track written practice attempts.

## Workflow

1. Create a learning course from a goal (2–8 lessons are generated).
2. Read a lesson prompt and optional hints.
3. Submit a written answer.
4. Inspect the transparent assessment: matched concepts, missing concepts, score, best score and XP.
5. Revisit lessons and inspect attempt history.

## Assessment limits

- The curriculum is generated by the selected primary model; no additional model is required.
- The initial evaluator uses deterministic phrase coverage against the lesson's expected concepts. It is intentionally transparent and lightweight, but it does not understand meaning, judge reasoning quality, or guarantee correctness.
- Scores are practice signals, not grades or claims of mastery. Review answers and improve the rubric for high-stakes use.
- XP is awarded only when a learner reaches a new score band on an exercise, so repeating an identical result cannot farm points.
- XP measures recorded practice progress only. It does not change model weights, prove intelligence gains, or imply the model learned permanently.
- Curricula and attempts are local SQLite records. They are not automatically converted into model training data.
- No shell, code execution, package installation, or autonomous external action is involved.

## TUI

```text
/learn create <goal>
/learn list
/learn show <course-id>
/learn answer <lesson-id> <written answer>
/learn attempts <lesson-id>
```

## Studio API

- `GET /api/learning/courses`
- `POST /api/learning/courses` with `{"goal":"Learn Python fundamentals"}`
- `GET /api/learning/courses/{course_id}`
- `POST /api/learning/lessons/{lesson_id}/answer` with `{"answer":"..."}`
- `GET /api/learning/lessons/{lesson_id}/attempts`

This is the first learning loop. Semantic grading, adaptive curriculum difficulty, and regression benchmarks remain future work.
